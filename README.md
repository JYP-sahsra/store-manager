# 매장관리 (3개 룸 정산)

매장 관리자가 휴대폰으로 3개 룸의 판매를 카운트하고, 선불·중간 결제를 처리하고, 하루 영업을 마감하는 웹앱(PWA)입니다.

- 판매 항목: 룸 이용 시간(시간당 요금), 주류, 기타 서비스
- 결제: 현금 = 판매액 − 할인 / 카드 = 판매액 × 1.1 − 할인
- 영업 중 데이터는 휴대폰에 저장합니다. 가격 설정과 일 마감 기록은 Supabase(클라우드 DB)에 저장합니다.
- 빌드 과정과 npm 의존성이 없습니다. 정적 파일을 그대로 GitHub Pages에 올립니다.

## 사용 흐름

하단 메뉴는 **룸**(영업 화면) / **매출**(일 마감·월 매출 캘린더·결제 내역) / **관리**(설정) 3개입니다.

1. **관리**: 룸 이름·시간당 요금, 판매 품목·가격, 관리자 이름, 매장 PIN을 입력하고 [설정 저장]을 누릅니다. 서버에도 함께 저장됩니다.
2. **룸**: 룸 타일은 상태별로 색이 다릅니다(대기 / 미결제 주황 / 결제 완료 초록). 손님이 오면 [손님 입장]을 누릅니다(입장 시각 기록). 룸 화면은 셀프 주문 앱처럼 위에 이용 시간, 아래에 분류 칩(주류 / 기타 서비스)과 메뉴 카드가 있고, 카드마다 `−` / `+`로 수량을 셉니다.
3. **결제**: 아래 고정 바의 [결제하기]를 누르면 직전 결제 이후 추가된 것만 계산합니다. 선불과 중간 결제를 여러 번 할 수 있습니다. 결제수단(현금/카드)을 고르고 할인 금액을 입력합니다.
4. **종료**: 미결제 금액이 0원이어야 종료됩니다. 남은 금액이 있으면 결제 화면이 먼저 열리고, 결제하면 바로 종료됩니다.
5. **매출**: 이번 영업일 요약과 결제 내역을 봅니다. 룸을 모두 종료한 뒤 [일 마감]을 누르면 서버에 저장하고 새 영업일을 시작합니다(파일 다운로드 없음). 마감한 매출은 같은 탭의 **월 매출 캘린더**에 날짜별로 표시됩니다. 업로드에 실패하면 휴대폰에 보관했다가 [다시 업로드]하거나 다음에 앱을 열 때 자동으로 올립니다.

**영업일 규칙**: 20시부터 다음날 12시(정오) 전까지의 영업은 모두 시작한 날의 매출로 기록합니다.
- 영업일은 [일 마감]을 누를 때까지 이어집니다. 자정을 넘긴 결제도 같은 영업일로 묶입니다.
- 영업일 날짜는 영업 시작(첫 룸 시작) 시각을 기준으로 정합니다. 기준 시각(기본 12시) 이전에 시작했으면 전날 영업입니다. 기준 시각은 설정에서 바꿀 수 있습니다.
- 마감을 빠뜨려 다음날 12시가 지나면 룸·매출 탭에 경고가 뜹니다. 이 상태에서 룸을 시작하면 지난 영업일 매출로 합쳐진다는 확인 창이 나옵니다.

## 개발

필요한 것: Node.js 18 이상 (개발 PC는 v24 확인)

```bash
npm run dev
```

- PC: http://localhost:5180 (포트 변경: `PORT=5190 npm run dev`)
- 휴대폰(같은 Wi-Fi): 실행할 때 출력되는 `http://192.168.x.x:5180` 주소로 접속합니다. 이 주소는 https가 아니라서 홈 화면 설치와 오프라인 동작은 되지 않습니다. 화면 확인용으로만 씁니다.

```bash
npm test
```

계산 규칙(`js/calc.js`)과 저장·검증(`js/storage.js`)을 테스트합니다.

PC 브라우저와 휴대폰은 데이터가 서로 따로 저장됩니다. 개발할 때는 PC에 테스트 데이터를 넣어 확인합니다.

## Supabase 설정 (최초 1회)

1. https://supabase.com 에서 무료 프로젝트를 만듭니다. 리전은 Northeast Asia (Seoul)을 권장합니다.
2. **SQL Editor**에서 `supabase/schema.sql` 전체를 붙여 넣고 실행합니다.
3. **PIN 설정**: SQL Editor에서 아래 문장의 `여기에-PIN`을 실제 PIN(6자리 이상 권장)으로 바꿔 실행합니다. PIN은 해시로만 저장됩니다. PIN을 채팅이나 저장소에 적지 마세요.
   ```sql
   insert into public.store_secret (id, pin_hash)
   values (1, extensions.crypt('여기에-PIN', extensions.gen_salt('bf')))
   on conflict (id) do update set pin_hash = excluded.pin_hash;
   ```
4. **Project Settings → API**에서 Project URL과 publishable(anon) key를 복사해 `js/config.js`에 넣습니다. **service_role / secret key는 절대 넣지 않습니다.**
5. 앱의 관리 탭에서 같은 PIN을 입력하고 [설정 저장]을 누릅니다.

### 보호 방식

- 테이블은 RLS로 막혀 있습니다. 앱은 PIN을 검사하는 함수 4개(`get_settings`, `save_settings`, `submit_day_close`, `list_day_closes`)만 호출할 수 있습니다.
- PIN이 10분 안에 10번 틀리면 10분간 모든 요청이 잠깁니다. 이때는 맞는 PIN을 넣어도 거부됩니다.
- publishable key는 페이지 소스에 공개됩니다. 키만으로는 데이터를 읽거나 쓸 수 없습니다.
- 관리자가 늘어나 개인별 권한이 필요해지면 Supabase Auth(개인 계정 로그인)로 바꾸는 것을 검토합니다.

### 마감 데이터 보기

- 앱의 매출 탭 → **월 매출 캘린더**: 날짜마다 그날 매출(만원 단위)과 월 합계가 나옵니다. `‹` `›`로 달을 옮기고, 날짜를 누르면 총매출, 현금/카드, 매상 구조, 룸별 매상, 품목별 판매를 봅니다. 같은 날 마감이 여러 번이면 합쳐서 표시합니다.
- Supabase **Table Editor → day_closes**에서도 볼 수 있습니다.

## GitHub Pages 배포

1. GitHub에 Public 저장소를 만들고 이 폴더를 push합니다.
2. 저장소 **Settings → Pages → Build and deployment**에서 Source를 `Deploy from a branch`, Branch를 `main` / `(root)`로 정합니다.
3. 몇 분 뒤 `https://<계정>.github.io/<저장소>/` 주소로 접속합니다.
4. 휴대폰에서 이 주소를 열고 홈 화면에 추가합니다. iPhone은 Safari 공유 → 홈 화면에 추가, Android는 Chrome 메뉴 → 앱 설치를 누릅니다.

새 버전을 배포한 뒤 휴대폰에 바로 반영되지 않으면 앱을 완전히 닫았다가 다시 엽니다. 앱 파일 목록을 바꿨다면 `sw.js`의 `CACHE` 버전을 올립니다.

## 데이터 백업

- 마감 기록은 서버(Supabase)에만 저장합니다. 일 마감 때 파일을 내려받지 않습니다.
- 업로드에 실패한 마감은 휴대폰에 보관했다가 다시 올립니다(매출 탭 [다시 업로드] 또는 다음 실행 때 자동).
- 영업 도중 휴대폰을 바꿀 때만 관리 탭의 [백업 내보내기] / [백업 가져오기]를 씁니다. 백업 파일에는 PIN이 들어가지 않습니다.
- 브라우저 데이터를 지우면 영업 중(마감 전) 데이터가 사라집니다. 마감한 데이터는 서버에 남습니다.

## 후속 작업

- 분할 결제: 받을 금액을 일부만 입력하고 남은 금액을 다음 결제로 넘기는 기능입니다. 결제 기록의 `coveredBase` 필드를 이 기능에 쓸 수 있도록 미리 넣어 두었습니다.
